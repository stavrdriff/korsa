# КОРСА — встановлення на хостинг (cPanel + Node.js)

Коротко: **залити папку `korsa` по FTP → створити застосунок у cPanel → натиснути «Run NPM Install» і «Start».**

---

## 0. Як це працює

Сайт і адмінка — це один Node.js-застосунок:

- відвідувачі отримують готові HTML-сторінки (`public/`), картинки (`img/`) і стилі (`assets/`);
- адмінка відкривається за адресою `https://домен/admin/`;
- дані адмінки зберігаються в базі `data/cms.sqlite`. Це SQLite, тобто звичайний файл: **окремо створювати базу в cPanel (MySQL) не потрібно**, вона заливається разом з іншими файлами.

---

## 1. Що потрібно від хостингу

| Вимога | Навіщо |
|---|---|
| cPanel з розділом **Setup Node.js App** | запуск сайту та адмінки |
| **Node.js 20 або 22** (краще 22) | на старіших версіях сервер не запуститься |
| **~1 ГБ** вільного місця | ~460 МБ файлів сайту, залежності та база |
| FTP-доступ | щоб залити файли |

---

## 2. Що заливати

Папку **`korsa`** цілком, як вона є. Всередині має бути:

```
korsa/
├── .env               ← налаштування (прихований файл — обов'язково залийте!)
├── app.cjs            ← файл запуску
├── package.json
├── package-lock.json
├── DEPLOY.md          ← ця інструкція
├── admin/             ← адмінка
├── assets/            ← стилі та скрипт сайту
├── data/
│   ├── cms.sqlite     ← база даних
│   └── uploads/       ← фото, завантажені через адмінку
├── img/               ← картинки та відео (~1650 файлів)
├── public/            ← сторінки сайту
└── server/            ← код сервера
```

> ⚠️ **`.env` — прихований файл** (назва починається з крапки). Перевірте, що FTP-клієнт його бачить і заливає. У FileZilla: меню *Сервер → Примусово показувати приховані файли*.
>
> **Не створюйте і не заливайте папку `node_modules`.** cPanel ставить залежності сам (крок 4.2). Якщо `node_modules` уже лежить у папці, панель видасть помилку.

---

## 3. Заливка по FTP

1. Підключіться до хостингу по FTP (FileZilla або інший клієнт).
2. Відкрийте **домашню папку** акаунта (`/home/ВАШ_ЛОГІН/`). **Не** `public_html`!
3. Перетягніть туди папку `korsa` цілком.
4. Дочекайтеся завершення. Файлів ~1760, це може зайняти 10–30 хвилин. Після завершення перевірте, що у вкладці «Невдалі передачі» нічого немає.

Результат: `/home/ВАШ_ЛОГІН/korsa/` з усім вмістом, як у п. 2.

---

## 4. Запуск у cPanel

### 4.1. Створити застосунок

cPanel → **Setup Node.js App** → **Create Application**:

| Поле | Що вказати |
|---|---|
| Node.js version | **22** (або 20) |
| Application mode | **Production** |
| Application root | **korsa** |
| Application URL | ваш домен (`korsadnipro.in.ua`) |
| Application startup file | **app.cjs** |
| Environment variables | нічого не додавати, усе вже є в `.env` |

Натисніть **Create**.

### 4.2. Встановити залежності і запустити

На сторінці застосунку:

1. Натисніть **Run NPM Install** і дочекайтеся повідомлення про успішне завершення (1–3 хвилини).
2. Натисніть **Start App** (або **Restart**, якщо застосунок уже запущений).

### 4.3. Прибрати старий сайт з `public_html`

Якщо на домені раніше був звичайний сайт (HTML-файли в `public_html`), Apache віддаватиме їх замість нового сайту. Тому:

1. **Зробіть резервну копію:** Файловий менеджер → `public_html` → виділити все → **Compress** → завантажити архів собі.
2. Перенесіть **усі файли** з `public_html` в окрему папку, наприклад `old_site`. Залиште лише `.htaccess`: його створила панель на кроці 4.1, у ньому є рядки з `Passenger`.
3. Відкрийте сайт. Тепер має відкриватися новий.

Якщо щось пішло не так, поверніть файли з `old_site` назад у `public_html`, і старий сайт знову працюватиме.

### 4.4. HTTPS

cPanel → **SSL/TLS Status** → виберіть домен → **Run AutoSSL**.

## 5. Перевірка

| Адреса | Що має бути |
|---|---|
| `https://домен/` | головна сторінка зі стилями та фото |
| `https://домен/catalog.html` | каталог |
| `https://домен/shtory-rymski.html` | сторінка з фото та відео |
| `https://домен/sitemap.xml` | список сторінок з **вашим** доменом |
| `https://домен/admin/` | форма входу |

**Вхід в адмінку:**

- логін: `valkorsaadmin`;
- пароль: `korsa` + дві цифри поточної хвилини **на вашому комп'ютері** (о 14:07 → `korsa07`).

Після входу відкрийте будь-яку сторінку в «Категоріях», змініть щось дрібне і збережіть. Зміна має з'явитися на сайті.

## 6. Налаштування (`.env`)

Файл `korsa/.env` можна редагувати прямо на хостингу: Файловий менеджер → *Settings → Show Hidden Files* → правий клік → *Edit*.

```dotenv
SITE_URL=https://korsadnipro.in.ua      # домен сайту, без слеша в кінці
SESSION_SECRET=...                      # випадковий рядок, не чіпати
ADMIN_USER=valkorsaadmin                # логін в адмінку
ADMIN_PASSWORD_PREFIX=korsa             # пароль = korsa + дві цифри хвилини
```

Після будь-якої зміни натисніть **Restart** у *Setup Node.js App*.

---

## 7. Оновлення сайту згодом

- **Оновився код** (`admin/`, `assets/`, `server/`, `app.cjs`, `package*.json`): перезалийте ці папки й файли по FTP і натисніть **Restart**. Якщо змінився `package.json`, спершу натисніть **Run NPM Install**.
- **Нові картинки:** залийте лише нові файли в `korsa/img/`, у відповідні підпапки.
- ⚠️ **Не перезаливайте `data/`, `public/` і `.env`**, якщо сайт уже редагують через онлайн-адмінку. Там лежать база й сторінки, згенеровані адмінкою, і перезаливка затре онлайн-зміни.

### Резервна копія бази

Періодично (і перед кожним оновленням) скачуйте по FTP файл `korsa/data/cms.sqlite` і папку `korsa/data/uploads/`. Робіть це, коли в адмінці ніхто не працює.

## 8. Якщо щось не працює

Помилки сервера пишуться у файл `korsa/stderr.log` (або в лог, на який посилається сторінка застосунку в cPanel).

| Симптом | Що робити |
|---|---|
| «Incomplete response» / 503 / застосунок не стартує | Перегляньте `stderr.log`. Перевірте, що *startup file* = `app.cjs`, а Node.js ≥ 20 |
| `Cannot find module 'express'` | Не встановлено залежності: натисніть **Run NPM Install**, потім **Restart** |
| Run NPM Install пише про папку `node_modules` | У `korsa/` залито папку `node_modules`. Видаліть її і натисніть **Run NPM Install** знову |
| `gyp ERR!` або помилка `better-sqlite3` під час встановлення | Виберіть Node.js 22 або 20 і повторіть. Якщо не допомогло, напишіть у підтримку хостингу |
| Відкривається старий сайт | У `public_html` лишились старі файли, див. п. 4.3 |
| Сайт без стилів або картинок | Залито не все. Порівняйте вміст `korsa/` зі списком у п. 2 |
| Не пускає в адмінку | Перевірте, що залито `.env`. Пароль = `korsa` + хвилина на вашому годиннику. Оновіть сторінку входу (Ctrl+F5) |
| Збереження в адмінці дає помилку `EACCES` | Немає права запису. Файловий менеджер → `korsa/public` і `korsa/data` → *Permissions* → 755 для папок, 644 для файлів |
| Після перезапуску знову просить увійти | Це нормально: сесії скидаються під час перезапуску |
| У `sitemap.xml` неправильний домен | Виправте `SITE_URL` у `.env` (п. 6) і натисніть **Restart** |

---

## 9. Про безпеку

- Пароль адмінки слабкий: секретом фактично є лише префікс `korsa`. Варто замінити його в `.env` на довший і нестандартний.
- `.env` і `data/` з браузера недоступні, сервер їх не віддає. Але ніколи не копіюйте їх у `public_html`.
